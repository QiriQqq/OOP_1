# Лабораторная работа №3 — тесты

## Запуск

Из корня распакованного архива:

```bash
dotnet test tests/OOP_3.Tests.csproj
```

Используются xUnit и NSubstitute. Тесты не обращаются к системным часам, настоящему генератору случайных чисел, сети или внешней базе данных.

## Задание 1. Инварианты и расчёт выплат

| Правило | Проверяющий тест |
|---|---|
| Часы в неделю от 1 до 60 включительно принимаются | `Hours_at_allowed_limits_are_accepted` |
| Часы меньше 1 или больше 60 отклоняются | `Hours_outside_allowed_range_are_rejected` |
| ФИО не может быть null, пустым или состоять из пробелов | `Empty_employee_name_is_rejected` |
| Непустое ФИО принимается | `Non_empty_employee_name_is_accepted` |
| Оклад, равный минимальному значению 20000, принимается | `Minimum_salary_is_accepted` |
| Оклад ниже 20000 отклоняется | `Salary_below_minimum_is_rejected` |
| Почасовая выплата рассчитывается как часы × 4 недели × ставка | `Hourly_employee_payment_uses_hours_weeks_and_hourly_rate` |
| Окладная выплата учитывает процентную премию | `Salaried_employee_payment_includes_percentage_bonus` |
| Выплата подрядчика равна сумме актов и премии | `Contractor_payment_is_sum_of_acts_and_bonus` |
| Процентная премия действительно прибавляется к выплате | `Percentage_bonus_is_not_ignored` |

## Задания 3 и 4. Дублёры и NSubstitute

В исходном репозитории нет `ShipmentService`, а вариант лабораторной требует подменять время для стажа, случайность для распределения задач и хранилище списка сотрудников. Поэтому те же роли реализованы на предметной области сотрудников через `EmployeeWorkflowService`.

| Зависимость | Ручной дублёр | Назначение |
|---|---|---|
| `ITimeProvider` | `FixedTimeProvider` | Возвращает фиксированную дату для расчёта стажа |
| `IRandomSource` | `FixedRandomSource` | Возвращает заданный индекс задачи |
| `IEmployeeStorage` | `InMemoryEmployeeStorage` | Хранит сотрудников в памяти |

Ручные проверки находятся в `EmployeeWorkflowServiceTests`. Проверки с NSubstitute находятся в `NSubstituteWorkflowTests`. В последнем тесте подтверждается, что `Save(employee)` вызван ровно один раз с тем же экземпляром сотрудника.

Для вычисляемого результата предпочтителен ручной фейк: он явно задаёт дату, индекс или содержимое хранилища и не привязывает тест к лишним деталям взаимодействия. Мок через NSubstitute нужен там, где проверяется само взаимодействие — например, ровно один вызов сохранения с конкретным сотрудником.

## Границы адаптации

Задание 2 пропущено по запросу. В задании 4 вместо отсутствующего учебного `ShipmentService` проверяются эквивалентные зависимости варианта из ЛР2. В исходном коде не было расчёта надбавки за стаж и распределения задач, поэтому добавлен небольшой отдельный сервис, не смешивающий эти операции с классами расчёта зарплаты.
